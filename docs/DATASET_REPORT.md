# Dataset and Data-Quality Report (Phase 2)

## 1. The shipped dataset
`ml/data/cognitive_risk_dataset.csv` (5,000 rows) was **generated by `generate_cognitive_dataset.py`**, not collected. It is now regenerated as `ml/data/synthetic_cognitive_screening.csv` with a `.meta.json` provenance file (`"synthetic": true`, parameters, SHA-256) that is propagated into the model artifact, the API and the UI.

Audit (`python ml/data_audit.py --csv ... --target risk_level`, full output in `ml/reports/`):

| Check | Result | Interpretation |
|---|---|---|
| Missing values / exact duplicates / conflicting duplicate vectors | 0 / 0 / 0 | Clean because generated, not because well curated |
| Out-of-range values (physical plausibility) | 0 | Values are clipped by the generator |
| Extreme outliers (3xIQR) | 0 | Clipping removes the tails real data have |
| Class balance | 46.6 / 33.5 / 19.9 % (ratio 2.3:1) | Mild; class weights used, no SMOTE |
| Single-feature one-vs-rest AUC >= 0.95 | `stroop_avg_reaction_ms` 0.954, `ad8_score` 0.953 | Red flag: real screening features rarely separate this cleanly |
| Label noise | 4% injected (adjacent classes) | Caps achievable accuracy at about 96% |
| Leakage | Features do not encode the label directly, **but** the label is the generating process: any model recovers the generator | Circular validation |
| Units / meaning | Dictionary in `data_audit.py` (years, ms, fractions, AD8 0-8) | `card_match_*` and `sequence_max_span` have no published norms |

**Conclusion.** Nothing in this file is evidence about Alzheimer's disease. It is retained only as a labelled development fixture.

## 2. Preprocessing and leakage controls (implemented)
* All preprocessing (median imputation, scaling, one-hot) is inside an sklearn `Pipeline`, so it is fitted on training folds only. A test asserts that scaler means equal the *training* means.
* Stratified 80/20 split; the test set is used once, after model and calibration decisions are made from training-only cross-validation.
* Imbalance: class weights (LR, RF). Resampling was rejected: imbalance is mild, and SMOTE would place synthetic points in validation data unless carefully nested.
* `family_history` one-hot (the old ordinal "unknown = 1" was an invented ordering).
* Inference never invents inputs; missing values are imputed with training medians and reported.

### Important scientific consequence
No public dataset contains AD8 + Card-Match + Stroop telemetry with clinical labels. Therefore the app now has two honest tracks:

1. **Digital-screening model** (the app's own features): synthetic prototype only, until you collect real consented data with clinician-assigned labels.
2. **Real-data model, OASIS-2** (`ml/train_oasis2_model.py`): dementia (CDR>0) vs non-demented from Age, Sex, Education, SES, eTIV, nWBV (+ MMSE as a second, optimistic feature set). It uses subject-grouped nested CV (373 visits come from 150 people, so row-wise splitting leaks), excludes CDR (it defines the label), drops ASF (deterministic transform of eTIV), includes prior-only and Age-only baselines (brain volume declines with age), and reports subject-cluster bootstrap CIs. **This pipeline is tested on an in-memory schema fixture only. It has not been run on real OASIS data**; I make no claim about its results. These features (MRI volumes, MMSE) are not collected by the current web app, so using this model in the app would be a design change.

### Synthetic-data policy
Synthetic data is allowed only for development/tests and is always labelled (`.meta.json`, artifact `validation_status`, API `model_info`, UI banner). The OASIS test fixture lives only in memory inside the unit test.
